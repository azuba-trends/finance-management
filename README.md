# Azuba Finance Manager

Offline-first personal finance tracker built with React, Vite, Capacitor, and local storage. The Android build uses the native SQLite database through `@capacitor-community/sqlite`; the browser preview uses IndexedDB as a local-only fallback. There is no login, Firebase, cloud database, analytics, or transaction sync.

## Features

- Dashboard totals for income, expenses, balance, Cash, and Online accounts.
- Add, edit, and delete income/expense records with category, account, description, and date.
- History search and filters for date, type, account, and multiple categories.
- Inclusive custom end-date filtering.
- Overview cashflow and expense charts based on the current History filters.
- Integer-paise amount storage to avoid common floating-point money errors.
- Versioned JSON backup and validated restore. Restore replaces current records only after explicit confirmation and runs atomically in the database.
- Mobile-first layout, independent scrolling, safe-area padding, and keyboard-aware scrollable transaction form.

## Requirements

- Node.js 20.19+ or 22.12+ recommended for Vite 8.
- npm.
- For Android: Android Studio, a supported Android SDK, Java/Gradle components compatible with the generated Capacitor project, and a physical device or emulator for testing.

## Run the browser preview

```bash
npm install
npm run dev
```

Browser preview data is stored in IndexedDB for that browser origin. Clearing browser site data can erase it. This is only the web fallback; the Android build uses SQLite.

## Generate the Android project

On a machine with internet access and Android development tools installed, run this once from the project folder:

```bash
npm install
npx cap add android
npm run android:sync
npx cap open android
```

The `android:setup` script is also provided for first-time setup (`npm run android:setup`). If the `android` folder already exists, do not run `cap add android` again; use `npm run android:sync` instead.

In Android Studio, allow Gradle sync to finish and run the app on an emulator or connected Android device. To build a debug APK from the project root after Android is generated:

```bash
npm run build
npx cap sync android
cd android
# Windows:
gradlew.bat assembleDebug
# macOS/Linux:
./gradlew assembleDebug
```

The debug APK is normally written to `android/app/build/outputs/apk/debug/app-debug.apk`.

For a release APK, configure a signing key in Android Studio and use **Build > Generate Signed Bundle / APK**. Do not commit or share private signing keys.

## Local data and backups

- Android transactions are stored in the app's local SQLite database.
- No login or cloud account is required.
- Uninstalling the app or clearing its data can remove the local database. Export JSON backups regularly and store them outside the app/device.
- Restore replaces the current transaction list after validation and confirmation. Export a backup of current records before restoring if you need to keep them.
- The new local-only app does not automatically import any old records that may still exist in the previous Firebase/Firestore app. The old cloud database is not contacted.

## Tests and checks

```bash
npm test
npm run lint
npm run build
```

Unit tests cover monetary conversion/validation, aggregate totals, and inclusive date range behaviour. A successful frontend build does not substitute for testing the generated APK on an Android device. Verify airplane-mode operation, transaction persistence after restart, scrolling with the keyboard open, backup export/restore, and small-screen behaviour before distributing the APK.

## Notes

- The Android project is generated by Capacitor using the documented commands. It is not pre-generated in this source archive because native project generation requires installing the platform packages and Android tooling.
- Keep the package lockfile generated by `npm install` when you begin development, so your own environment's dependency resolution stays reproducible.

## Build an APK without installing Android Studio (GitHub Actions)

This repository includes `.github/workflows/android-apk.yml`. GitHub Actions can build a **debug APK in the cloud**, so Android Studio is not required on your computer.

1. Extract this ZIP.
2. Upload/push the project files to a GitHub repository you control, making sure `.github/workflows/android-apk.yml` is included.
3. Open the repository on GitHub and select **Actions**.
4. Select **Build Android APK**. For a manual build, choose **Run workflow** and select your branch. A push to `main` or `master` also triggers a build.
5. Open the completed workflow run and download the artifact named `finance-manager-debug-apk` under **Artifacts**.
6. Extract the artifact to obtain `app-debug.apk`, then transfer it to your Android phone and install it. Android may ask you to allow installation from that source.

The workflow runs tests, lint, the web build, generates the Capacitor Android project, and attempts the debug APK build. If any step fails, open the failed workflow step and inspect its log; do not treat a failed run as a completed APK build. This produces a **debug APK**, not a signed production release. For release distribution, create and protect a signing key and configure a separate signed-release workflow.

No Android Studio is needed locally, but a GitHub account/repository and a successful GitHub Actions run are required for this cloud-build method. GitHub Actions usage limits may apply to your account.
